**Product**: PersonalPaper v2
**Release**: v2.1.3 (a feature release on the v2.1 system, after the vocabulary releases `docs/prds/v2.1.1-topic.md` and `docs/prds/v2.1.2-subtopic.md`)
**Owner**: Patrick
**Date**: 2026-10-25
**Status**: Approved 2026-10-25. The owner set the scope that day: a topic definition says how often the topic runs, first used to run the aviation topic once a day in the morning, with its anniversary items taken from dated archives so that the run's timing is independent of when the sources publish. The first draft named the routine's two fires (morning, evening) in the definition; the owner asked for the topic to say how many runs a day and from what time, with each fire checking a run register, and approved that revision with the word "cadence". Build and cutover recorded in section 11.
**Scope in one line**: a topic's cadence says how many runs a day it takes and from what time, a deterministic tool decides at each fire which topics are due from their cadence and their run records, and a feed URL can carry the edition's date so a topic can read a date's archive.

---

## 1. Summary

Every topic runs at every fire of the shared routine, 05:05 and 17:05 America/New_York, and the later run is the day's edition. The definition's `cadence` field is prose; nothing reads it as a schedule. The aviation topic's reader wants one paper a day, in the morning.

Running it in the morning alone exposes a coupling between when a topic runs and what its sources have published by then. The two anniversary columns post each anniversary on the day itself: This Day in Aviation between about 03:00 and 13:00 ET (17% of posts out by 05:05, 72% by 09:00, 95% by noon, over 120 posts and 27 days to 2026-10-25), and Vintage Aviation News's column between 09:00 and 09:31 ET every day. A 05:05 run would see almost none of the day's anniversaries in their feeds.

Both sites keep dated archives. This Day in Aviation republishes each post every year on its anniversary, and a republished post moves to its new date, so the date's posts are always on two archive pages between them: this year's (posts already out) and last year's (posts not yet out). The page tool's way of fetching reads both. So the edition can carry the date's anniversaries whenever it runs. This release adds what that takes: a structured cadence, a tool that applies it, and feed URLs that carry the edition's date.

**The lesson for other topics.** A source's publishing time is part of its fit to a topic, alongside volume, description length and recency. The guide's source research gains a timing check (D6).

## 2. The word

**Cadence**, the field the definition already has and the word the vision uses ("Editions by cadence and mode", section 17's list of what a topic carries). The owner confirmed it on 2026-10-25 over "frequency", which names only how often. One word for the thing: the existing field gains structure, and no second word is added beside it.

**Run register.** The runs table the hosted environment already keeps: one record per run, with topic, start time and status, read through `pp.mjs runs`. Nothing new is stored.

## 3. What changes

**The definition.** `cadence` becomes an object:

```json
"cadence": {
  "runs_per_day": 1,
  "from": "05:00",
  "timezone": "America/New_York",
  "note": "One edition a day, ready by early morning Eastern time."
}
```

A topic's run times start at `from` and are spaced evenly across the day, 24 / `runs_per_day` hours apart; a time past midnight is dropped. One a day from 05:00 is 05:00; two from 05:00 are 05:00 and 17:00. `timezone` defaults to America/New_York. `note` is the prose the field carried before. A cadence that is still a string, or has no `runs_per_day`, runs at every fire, which is the behavior before this release, so the two existing topics need no new version.

**The due tool.** `node agent/tools/due.mjs`, deterministic, run once at the start of every fire. For each topic in the index it counts today's runs (the date in the cadence's timezone) that closed `ok` or `degraded` or are still `running` (a run left running for more than two hours counts as abandoned), and the run times that have passed. The topic is due when the first number is smaller. It prints the due list and, for each skipped topic, the reason.

What follows from the rule:

- **A manual fire is safe.** It does not run a topic twice: aviation, run at 05:05, is skipped at a 14:00 manual fire, and the general topic is skipped there too until its 17:00 time has passed.
- **A missed run is made up.** A run that failed at 05:05 leaves the topic due, so the next fire, scheduled or manual, runs it.
- **Fires and topics are decoupled.** The routine only has to fire at least as often as any topic's run times; with every topic at one or two a day, the two fires suffice. More fires later need no definition change, at the cost of a cloud session per fire even when nothing is due.
- **A run given a list of topics runs them whatever the cadence**, for a deliberate re-run.

**The agent.** It runs the tool first and takes its due list as the topics to run; the routine's prompt says so in place of "every topic in the registry index". A skipped topic gets no run record, one line in the session's output. The same-day rule is unchanged: the latest run is the edition, earlier runs fold beneath it.

**The feed tool.** A feed URL may carry tokens from the edition's date (UTC, as the agent already uses):

| Token | Meaning | 2026-10-26 |
|---|---|---|
| `{yyyy}` | year | 2026 |
| `{yyyy-N}` | year minus N | `{yyyy-1}` is 2025 |
| `{mm}`, `{dd}` | month and day, two digits | 10, 26 |

A feed whose URL carries a date token is a **dated feed**: its window does not apply, and every item it returns is a candidate, because the URL already chose the date. A dated feed that answers 404 has nothing for that date and counts as empty, not failed. A feed entry marked `"page": true` is an HTML page read in place of RSS: the tool fetches it as the page tool does and takes as items the headings that link to articles on the page's own host (the WordPress `entry-title` pattern first, then any `h1` to `h3` containing a link), following the next-page link (`rel="next"`, a `next` class, or a `/page/N/` link) up to three pages. Page items carry no date and no description; the coverage step reads each one. For testing, `--date` sets the edition date and `--definition` reads a local definition.

**Duplicate collapse.** Items from a page collapse with others by link only. This Day in Aviation's titles are dates ("26 October 1962" twice on one page, two posts), so collapsing by title would merge different posts.

**The Worker.** The listing page's "updated twice daily" copy says each topic updates as often as its cadence says. No other change.

## 4. The aviation topic, definition v3

- `cadence`: one run a day from 05:00 America/New_York.
- **This Day in Aviation**: the live feed is replaced by two dated archive pages, `https://www.thisdayinaviation.com/{yyyy}/{mm}/{dd}/` and `{yyyy-1}`, with `page: true`. Proven at build: for 25 October, this year's page held all six posts (all out by then) and last year's was empty; for 26 October, before any were out, last year's page held all four.
- **Vintage Aviation News, Today In Aviation History**: the category feed is replaced by the site's dated archive feeds for the two prior years, `https://vintageaviationnews.com/{yyyy-1}/{mm}/{dd}/feed/` and `{yyyy-2}`. These carry the whole day's posts, of which the anniversary column is the candidate: about one a date, sometimes repeating an event across years. The column posts at 09:00 ET, after the 05:05 run, so this year's is never available in time.
- **NASA History** unchanged. **The museum and heritage feeds** unchanged: with one run a day their 48-hour windows overlap by a day, and the archive check removes repeats as it does today.
- The this-day scope note says the candidates come from dated archives and that a post's own publication date is the year it last ran; the date that matters is the event's, in the title or text.
- The topic's overview is updated in the same session (`docs/defining-a-topic.md` section 7).

## 5. What does not change

The routine's schedule (two fires); the two existing topics' definitions; the edition date (UTC); the same-day folding; the candidate record and the cuts page, which show dated-feed and page items like any other.

## 6. Decisions

Taken 2026-10-25: D1 and D2 by the owner, the rest on the session's recommendation with the owner's go.

**D1. The word: cadence.** The existing field, made structured; no new field.

**D2. The shape: runs per day and a first run time.** No reference to the routine's fires, so the definition says what the reader wants and the routine stays an implementation detail. Weekly or weekday cadences, and run times the routine does not fire at, are deferred; the shape extends to the first with a `days` list.

**D3. A deterministic tool decides, from the run register.** The agent does not judge whether a topic is due. No run record for a skipped topic, so the runs table stays a record of work done. "Today" is the cadence's timezone; the edition date stays UTC, and the two agree for fires before 20:00 ET, which both are.

**D4. Dated feeds and page feeds in the feed tool.** This is the "page role" the climate research asked for on 2026-10-23, in the narrow form an index page needs; the climate topic's agency pages (the Drought Monitor's weekly map, Copernicus bulletins) can use it later, each a definition change.

**D5. Aviation v3 as section 4.** The two live anniversary feeds are dropped: at 05:05 they would add only the day before's posts, which the scope note excludes.

**D6. The guide.** `docs/defining-a-topic.md` documents the cadence field and the date tokens in its table, drops "a cadence of its own is a system change", and adds a fourth measure to the source research: when each source publishes, against the topic's runs, with dated archives as the remedy for date-bound material.

**D7. Cutover: one commit before the morning fire.** The tools, the agent, the Worker copy and the guide in one commit, pushed (the routine checks out `main`); the Worker deployed; the routine's prompt updated to run the due list; aviation v3 posted. The first test is the 2026-10-26 05:05 ET fire. Package version 2.1.3.

## 9. Risks

| Risk | Likelihood | Handling |
|---|---|---|
| This Day in Aviation blocks the page fetch from the cloud egress | Low to medium | The fetch works from here with the page tool's headers; a blocked fetch shows as a failed feed in the first morning run, and the fallback is a later run time for this topic |
| The site stops republishing a post, so a date's pages run short | Low | The two pages hold four to six posts a date in October; the editor's cap is five and NASA History adds space anniversaries |
| A run hangs in `running` and blocks the topic for the day | Low | A running record older than two hours does not count |
| A fire after 20:00 ET counts runs against a different date than the edition's | Low | Neither fire is that late; a later fire would need the rule restated |

- Cadence shown to the reader on the edition page.

## 11. Build and cutover

**Cut over 2026-10-25.** Commit 97fa0cc pushed at 21:32 UTC; Worker deployed (version 5fc85bcf); the routine's prompt changed to run the due tool's list; aviation v3 posted. The due tool, run against the live register, skips aviation that evening ("1 of 1 run(s) due by now already made today") and lists all three for 05:05 ET on 2026-10-26.

**Found after the cutover: This Day in Aviation schedules its reposts.** An hour after the build proved last year's 26 October page at four posts, it held two, and the other two answered 404 at their own addresses: the site schedules each anniversary repost ahead, about the evening before, and a scheduled post is hidden everywhere until it goes out. The two-page reading of section 4 therefore holds only the posts that are neither scheduled nor yet out; at 05:05 that is about one post in six. The dated feeds work as built, and Vintage Aviation News's archives, which it does not repost, are stable. The aviation topic's this-day section will run short at 05:05.

The owner chose on 2026-10-25 to hold any change to the aviation definition until its reader's feedback. The options put to the reader, in the topic's overview: 05:05 as now; a third fire at 10:05 ET with the topic's cadence from 10:00, where the live feeds carry about 80% of the posts and the day's column (the cadence design makes the other topics skip such a fire on their own); or one run a day from 13:00, which is the 17:05 fire. The guide's timing check gains the second lesson: a dated archive helps only when the site does not move posts between dates.
