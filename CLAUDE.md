# personal-paper: working drive

You are working in the personal-paper working drive. This file is the session contract. The drive's working files (`_active-projects/`, `_explorations/`, `_readme.md`) are local and gitignored: they track the owner's work and are not part of the public release.

The drive map and conventions are in `_readme.md`, a local file that is not in the repository. Read it first when it exists. In a checkout without it (a cloud routine, a contributor's clone), the public `README.md` describes the system and `agent/instructions.md` is what a run follows.

## Session behavior

- **Orient first.** Read `_active-projects/_project-tracker-root.md` at session start for what is in flight. For project work, read that project's `_project-plan-[x].md` and `_project-tracker-[x].md` before starting; sub-projects carry their own pair (see Meta naming in the drive map).
- **Trackers.** Before finishing any task, update the relevant tracker: completed items move to the project tracker's Done with a `✓ YYYY-MM-DD` stamp; items you surface go to the root tracker's SFL (if it reads as intent; SFL is where future projects and releases are defined) or Someday Maybe (if merely a possibility). Project trackers carry MTG and Done only. Never add to MTG; promotion is Patrick's.
- **Outputs.** Land in the relevant project folder in `_active-projects/[x]`, the topical folder for standalone knowledge work, or a dated directory in `_explorations/` for open thinking that is not yet work. Never at the root. Scoped work carries a plan and a tracker; unscoped work carries neither, by design.
- **Canonical documents** (the unprefixed topical folders) are read-only references unless the task is explicitly their revision.
- **Voice.** Written output uses declarative prose and bold inline labels for topic labels; no em-dashes in prose (commas and semicolons instead; en-dashes in numeric ranges); no "not X but Y" constructions.
- **When unclear, ask.** If goal, audience, or output format is unclear, ask before executing.
